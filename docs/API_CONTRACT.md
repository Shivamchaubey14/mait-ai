# API contract — v1 (frozen)

Base URL: `/api/v1/`

This file is the **frozen contract** the three workstreams build against, per SRS §12 Phase 1.
Backend implements it, mobile and admin-web consume it. Changing a signature here after the
freeze requires an ADR in [`adr/`](adr/) and sign-off from all three workstream leads.

The live, authoritative schema is generated by drf-spectacular:

| Artifact | URL |
| --- | --- |
| OpenAPI 3.0 schema | `/api/schema/` |
| Swagger UI | `/api/docs/` |
| Redoc | `/api/redoc/` |

CI fails the build if the committed `backend/openapi.yaml` drifts from the generated schema,
so this contract cannot silently rot.

---

## Conventions

**Auth** — every endpoint except login and OTP-send requires `Authorization: Bearer <access>`.

**Pagination** — limit/offset on all list endpoints:

```json
{ "count": 1240, "next": "...?limit=50&offset=50", "previous": null, "results": [] }
```

**Errors** — RFC 7807 problem details:

```json
{
  "type": "https://api.maitai.in/errors/validation-error",
  "title": "Validation failed",
  "status": 400,
  "detail": "Straw 3391027744 is not in your current stock.",
  "errors": { "straw_unique_no": ["not_in_stock"] }
}
```

**Idempotency** — `POST /ai-events/`, `POST /ai-events/{id}/complete/` and `POST /indents/`
accept an `Idempotency-Key` header. A repeat of the same key within 24 hours returns the
original response instead of re-executing. This is what makes the offline queue safe to retry.

**Rate limits** — OTP send/verify is throttled per mobile number and per IP. Exceeding it
returns `429` with `Retry-After`.

## Critical flow — AI event happy path

The sequence mobile implements. Every transition is validated server-side; none can be
skipped or backdated from the client.

```
POST   /ai-events/                      { mpp, member|non_member, animal, straw_unique_no }
       └─ 201 { id, status: "draft" }
GET    /semen-batches/{no}/validate/    → 200 in_stock:true  |  400 not_in_stock / already_used
       └─ status: "straw_verified"
PATCH  /ai-events/{id}/photo/           multipart: photo, gps_lat, gps_lng
       └─ status: "photo_captured"
POST   /payments/{id}/initiate/         { mode: "COD" | "ONLINE", amount }
       └─ status: "payment_pending", OTP dispatched to member mobile
POST   /payments/{id}/otp/verify/       { otp }
       ├─ ONLINE → POST /payments/{id}/proof/       { utr_number, screenshot }
       └─ COD    → POST /payments/{id}/cod-confirm/ { otp }   (second OTP)
POST   /ai-events/{id}/complete/        Idempotency-Key: <uuid>
       └─ 200 { status: "completed" }   ← straw deducted in the same transaction
```

`complete` is the only endpoint that mutates inventory. It fails closed: if payment is not
`verified`, it returns `409` and the straw is untouched.
